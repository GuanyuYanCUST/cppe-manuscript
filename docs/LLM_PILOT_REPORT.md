## 5. 复现性失败分析(验收 #4)

同一提示 5 次重放(temperature=0):
- 4/5 完全一致(含 purpose/ttl_min 等全部钉死);
- #0 漏 `purpose` 条件、#4 把 `ttl_min` 从 `["le",30]` 放宽为
  `["any",null]` —— 两次漂移方向都是**放宽一个收紧条件**;
- completion_tokens 67–138 波动,来源是思考阶段的服务端非确定性
  (GLM-5.3 始终思考),客户端不可消除。

三个处理选项(待您决定,不自行重跑):
1. 主跑引入自洽投票(k=3 取多数)并将复现口径改为"多数规则语义
   一致",预算按 3 倍候选调用重估;
2. 维持单次调用,复现性如实报告为 0.60 并在论文中作为"推理模型
   非确定性偏宽"的实测发现(与 PG 的确定性防护互为论据);
3. 复现口径改为 action+resource 一致(5/5=100%),条件层差异单列。
